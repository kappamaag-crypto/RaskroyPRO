# Резервные копии Раскрой PRO 5.3

## Где хранятся данные

- **Рабочий проект** сохраняется после изменения в `localStorage` браузера под прежним ключом `cutting_pro_5` (совместимость с версией 5.2).
- **История снимков** записывается в отдельную базу `IndexedDB` — `raskroy_pro_local_backups`, хранилище `snapshots`.
- Никаких запросов к серверу для расчёта или хранения данных приложение не выполняет. GitHub Pages только раздаёт статические файлы сайта.
- Снимок содержит заказ, детали, закупочные хлысты, складские остатки, журнал проведённых операций, метки проведённых заказов и последний проведённый отчёт, если есть.

## Автоматические копии

После первого открытия создаётся снимок «Начало сеанса». После ввода или изменения исходных данных — новый снимок через **12 секунд без дополнительных изменений**. Изменение ввода сразу сохраняется в `localStorage`, но новый архивный снимок появляется с задержкой. Хранятся последние **12 автоматических** снимков.

## Защитные копии

Перед каждым из действий создаётся отдельная копия текущего состояния:

1. «Провести склад» — дополнительно сохраняется копия после проведения.
2. «Новый заказ» — дополнительно сохраняется копия после создания заказа.
3. «Сбросить на пример» — дополнительно сохраняется копия после сброса.
4. Импорт JSON, деталей CSV и таблиц из Excel — снимки до и после.
5. Удаление строки деталей либо доступных хлыстов — перед удалением.
6. Восстановление архивного снимка — исходное состояние архивируется перед восстановлением, а восстановленное — после.

Если база IndexedDB недоступна/переполнена, перечисленные операции **не выполняются**, а программа показывает предупреждение. Сохраняйте JSON на внешний диск, затем устраните причину ошибки.

Предусмотрено до **20 защитных и ручных** снимков. Старые снимки удаляются по принципу FIFO. Это не бесконечная история и не общая база склада.

## Как восстановить проект

1. Откройте тот же браузер и тот же адрес калькулятора, на котором работали ранее.
2. Нажмите **«♻ Резервные копии»** в верхнем блоке «Проект» либо вкладку «Резервные копии».
3. Найдите нужную запись по времени, номеру заказа, количеству складских позиций и числу операций журнала.
4. Для дополнительной безопасности нажмите **«↓ JSON»** рядом с копией, чтобы сохранить её на диск.
5. Нажмите **«Восстановить»**, подтвердите замену. Программа проверит целостность снимка, совместимость формата и предварительно архивирует текущий проект.
6. Проверьте ведомости, журнал и склад; если нужно, снова рассчитайте раскрой. Скачайте JSON.

Вместо этого можно нажать **«↑ Открыть проект JSON»** и выбрать ранее скачанный файл. При нормальном состоянии калькулятора перед импортом создаётся защитная копия. При повреждённом/неизвестном формате старой записи она отдельно архивируется как исходный текст до замены, и её можно скачать из раздела копий.

## Обновление 5.2 → 5.3

Новый формат данных — версия **7**, старый — версия **6**. При запуске 5.3 сохранённый проект проверяется. Прежде чем перезаписать рабочие данные новым форматом, приложение записывает исходный документ в IndexedDB. Нельзя терять ведомости деталей, остатки склада, проведённые заказы и журнал операций. Неподдерживаемые будущие версии, повреждённый JSON и ошибки структуры блокируют автоматическую перезапись.

## Ограничения и безопасность

- IndexedDB и localStorage — оба браузерные хранилища. **Очистка данных сайтов может удалить их одновременно**.
- Снимки привязаны к конкретному адресу. Переход, например, с `kappamaag-crypto.github.io` на `raskroy.spk-effa.ru` требует переноса проекта через JSON; встроенная миграция между доменами невозможна.
- Приватный режим, политики безопасности браузера, ограничения объёма хранения или `file://` могут помешать IndexedDB. Надёжнее использовать GitHub Pages через HTTPS.
- Не открывайте и не редактируйте один склад параллельно в нескольких вкладках: это независимые копии состояния с риском перезаписи изменений.
- Встроенная контрольная сумма проверяет случайные повреждения данных, **не является криптографической подписью** и не защищает от вредоносного изменения файлов.
- Фоновая загрузка JSON на диск без разрешения пользователя браузером не гарантируется. Настройте собственную процедуру: в конце рабочего дня скачать JSON и сохранить копию на внешний диск или SSD.
- Визуальное, технологическое и производственное тестирование раскроя остаётся обязательным.
