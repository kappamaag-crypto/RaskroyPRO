# Раскрой PRO 5.3.0

**Бесплатный клиентский калькулятор одномерного раскроя металлопроката.** Профильная труба, швеллер, уголок, двутавр, арматура и линейный прокат. Без сервера, API и регистрации.

> **Производственное ограничение.** Калькулятор предоставляется «как есть». Расчёты справочные: геометрию, пропилы, технологию резки, остатки, допуски и карты должен проверить технолог перед резкой. Доказательство оптимума выводится только для полностью решённых небольших задач.

## Как запустить

1. Откройте `index.html` в Chrome, Edge или Firefox либо используйте GitHub Pages.
2. Заполните ведомость деталей (сечение, сталь, длина в миллиметрах, количество).
3. Добавьте доступные закупочные хлысты и складские остатки. Для **складского** отрезка укажите конечное количество.
4. Установите ширину пропила, подрезку торцов и порог полезного остатка.
5. Выберите **цель** (минимум закупаемой длины / стоимости / отходов), **режим** и **политику склада**.
6. Нажмите **«Рассчитать раскрой»**. Проверьте карты, координаты, баланс и возвратные остатки.
7. При фактической резке, после сверки с реальностью, выполните **«Провести склад»**. Защитные копии будут созданы до и после операции; дополнительно скачайте JSON на диск.

При необходимости выгрузите Excel-отчёт, CSV или распечатайте карты. Данные не синхронизируются между браузерами. Текущий проект хранится в localStorage, резервные копии — в IndexedDB, перенос выполняется через JSON.

## Новые возможности 5.3.0 — резервное копирование

- **Автоматические снимки:** при запуске программы и через ~12 секунд после последнего изменения. Сохранение основного рабочего проекта в `localStorage` происходит сразу при изменении.
- **Версии проекта:** последние 12 автоматических и 20 защитных/ручных снимков в отдельном хранилище `IndexedDB`.
- **Восстановление:** кнопка **«♻ Резервные копии»** → выбрать дату/заказ → **«Восстановить»**. Перед заменой текущего проекта создаётся его защитная копия.
- **Защита опасных действий:** перед проведением склада, новым заказом, сбросом, импортом JSON/CSV/Excel и удалением строки программа создаёт снимок. Если IndexedDB не работает, действие отменяется.
- **Совместимость:** переход формата 6 → 7 с архивированием исходной записи перед миграцией. Неизвестный новый или повреждённый формат не сбрасывается автоматически на пример и не затирается.
- **Внешняя копия:** кнопка **«↓ Скачать текущий JSON»** сохраняет файл на компьютер. Для долговременного хранения рекомендовано копировать его на SSD или в другой независимый архив.

**Никакой серверной части не добавлено.** IndexedDB и localStorage привязаны к происхождению сайта (домен/протокол/порт) и браузерному профилю. При очистке данных сайта, работе в приватном режиме, смене браузера или домена локальные копии могут исчезнуть. Не считайте встроенные копии заменой внешнего JSON.

Подробно: [docs/BACKUPS.md](docs/BACKUPS.md).

## Новые возможности 5.2.0

- **Best Fit Decreasing (BFD)**: отдельный стартовый план.
- **Local Search / Swap**: переносы и перестановки деталей между хлыстами.
- **Ruin & Recreate**: пересборка части схем с сохранением складских ограничений.
- **Beam Search**: ограниченный параллельный поиск нескольких вариантов.
- **Pattern Generation**: генерация разнообразных схем для поиска.
- **Branch & Bound**: доказательство минимума закупаемой длины при одном покупном типоразмере, до 28 деталей.
- **Integer Pattern Optimization**: точный перебор целочисленных сочетаний схем для малых задач, до 13 деталей, 4 типоразмеров деталей и 3 типов хлыстов. **Это не универсальный MILP-решатель.**
- Новая настройка **«Приоритет складских остатков»**: экономический / строгий.
- **Точный** режим (помимо быстрого, сбалансированного, углублённого); явный статус доказательства либо его отсутствия.

### Политика склада

| Режим | Правило |
|---|---|
| Экономический | Сначала минимизируется выбранная целевая функция; складские остатки используются, если улучшают раскрой. |
| Строгий | Сначала максимизируется количество израсходованных физических складских хлыстов, потом оптимизируется целевая функция. Может быть дороже и увеличивать отходы. |

Строгая политика **не является гарантией** полного расходования доступного склада, если это несовместимо с заказом. В эвристических режимах она также не гарантирует математически максимального числа использованных складских хлыстов.

### Ограничения точного поиска

Детали и исходные длины допускают дробные значения до **0,001 мм**. Варианты решения являются полными только если не истекли лимиты узлов / времени и не превышены перечисленные ограничения. При недоказанном результате приложение показывает «Оптимальность не доказана». Точные алгоритмы могут быть ресурсоёмкими и в текущей версии выполняются в основном потоке браузера. Подробнее: [docs/ALGORITHMS.md](docs/ALGORITHMS.md).

## Проверка расчётного ядра

Достаточно Node.js 22+:

```bash
node --test tests/*.test.cjs
```

Тесты охватывают полноту количества деталей, складские квоты, баланс длин, дробные миллиметры, два приоритета склада, точные доказательства для малых задач и 100 детерминированных сравнений режимов. Дополнительно тестируются проверка версий и защитные ограничения формата сохранённых данных. Ручная проверка технологических карт на производстве остаётся обязательной.
